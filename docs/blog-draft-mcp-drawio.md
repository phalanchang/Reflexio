# Claude Code × draw.io MCP サーバーで設計図を自動生成してみた

## はじめに

アウトプットに挑戦ということで、やってみたことをぽちぽちとアウトプットしてこうと思います。
今回は最近話題に上がっていたdraw.ioのMCPサーバを試してみました。
今回、Claude Code の MCP（Model Context Protocol）サーバー機能を使って、**コードを読ませるだけで draw.io のダイアグラムを自動生成**できたので、その手順と感想をまとめます。

## 結論
MCPサーバを使用することで、出力のクオリティが上がり、とても満足です。

## MCP サーバーとは

MCP（Model Context Protocol）は、AI アシスタントに外部ツールとの連携機能を追加するプロトコルです。Claude Code では `.mcp.json` に設定を書くだけで、様々な外部ツールを AI に使わせることができます。

今回使用したのは draw.io 公式の MCP サーバー `@drawio/mcp` です。

## セットアップ

プロジェクトルートに `.mcp.json` を配置するだけです。

```json
{
  "mcpServers": {
    "drawio": {
      "command": "npx",
      "args": ["-y", "@drawio/mcp"]
    }
  }
}
```

下記のコマンドで作成してもらいました。

```
claude mcp add --transport stdio --scope project drawio -- npx -y @drawio/mcp
```

設定後に Claude Code を再起動すると、draw.io 関連のツールが使えるようになります。

## 実際にやってみた

### お題

React + Express + MySQL 構成の Web アプリで、「やりたいこと」を登録してから DB に格納されるまでの処理フローを図にしてもらいました。

### 手順

Claude Code に以下のように依頼しただけです。

```
「やりたいこと機能」でやりたいことを入力して、DBに格納するまでの流れをdraw.io形式で出力してほしいです。
mcpサーバとの接続を用意しましたので、使ってみてほしいです。
```

すると Claude Code が以下を自動で行いました。

1. **コードの読み取り** — フロントエンド（`WishForm.js`）とバックエンド（`routes/wishes.js`）のソースコードを読み込み
2. **フロー分析** — ユーザー入力 → バリデーション → API 通信 → 認証 → DB 操作 → レスポンスの流れを把握
3. **ダイアグラム生成** — Mermaid 記法でフローチャートを構成し、MCP サーバー経由で draw.io に送信
4. **ブラウザ表示** — 自動的にブラウザが開き、ダイアグラムが表示された

### 生成された図

フロントエンド → バックエンド → データベースを跨いだフローチャートが生成されました。

- フロントエンドのバリデーション（タイトル空チェック）
- `fetch()` による API 呼び出し
- `requireAuth` ミドルウェアによる認証
- サーバー側バリデーション
- `INSERT INTO wishes` による DB 格納
- タグのループ処理（`INSERT IGNORE` → `SELECT` → `INSERT wish_tags`）
- 画像アップロードの後処理

といった一連の流れが、色分けされたノードで表現されていました。

### ファイル保存

さらに「`.drawio` ファイルとして保存して」と依頼すると、スイムレーン形式（Frontend / Backend / Database の3レーン）の XML ファイルを生成してくれました。このファイルは draw.io デスクトップアプリや VS Code の Draw.io Integration 拡張機能でそのまま開けます。

## 良かった点

- **コードを読ませるだけ** — 自分で処理フローを整理する手間が省ける
- **ブラウザで即プレビュー** — 生成した瞬間に確認できる
- **セットアップが簡単** — `.mcp.json` に数行書くだけ
- **編集可能な形式で出力** — `.drawio` ファイルとして保存すれば、後から自由に編集できる
- **コードの実装に忠実** — 実際のソースコードを読んでから図を作るので、ドキュメントと実装の乖離が起きにくい

## 注意点

- MCP サーバーの設定変更後は **Claude Code の再起動が必要**
- ブラウザに表示されるのは一時的な URL なので、保存したい場合は `.drawio` ファイルへの出力を別途依頼する
- 複雑な図の場合、レイアウトの微調整は draw.io 上で手動で行った方がよい

## まとめ

draw.io の MCP サーバーを使うことで、「コードを読んで → 図を作って → ファイルに保存して」という一連の流れを Claude Code との対話だけで完結できました。設計ドキュメントの作成やコードレビュー時のフロー確認など、活用の幅は広そうです。

MCP サーバーは draw.io 以外にも様々なツールに対応しているので、自分の開発ワークフローに合わせて組み合わせてみると面白いと思います。
