# 01. ペルソナ定義書

## プライマリペルソナ

### 基本プロフィール

| 項目 | 内容 |
|---|---|
| **名前** | Phalanchang（ファランチャン） |
| **年齢** | 36歳 |
| **職業** | プロジェクトマネージャー / エンジニア |
| **業務内容** | ソフトウェア開発・保守のPM業務 |
| **管理範囲** | 複数プロジェクト・タスク・サービスを横串で統括 |

### 業務特性

#### 日常の業務フロー
1. **朝**: 複数プロジェクトの進捗確認、優先度の見直し
2. **午前**: チームへの指示出し、レビュー、ブロッカー解消
3. **午後**: ステークホルダーとの調整、設計・技術判断
4. **夕方**: 翌日の計画立て、残タスクの棚卸し

#### 管理対象の規模感
- **プロジェクト数**: 3〜5件を同時並行
- **管轄チームメンバー**: 5〜15名
- **サービス/システム**: 複数のプロダクト・マイクロサービス
- **ツール数**: 10+（Jira, Slack, GitHub, Notion, Google Calendar 等）

#### 技術バックグラウンド
- エンジニア出身（コードを読める・書ける）
- アーキテクチャ設計の判断ができる
- DevOps / CI/CD の基本知識あり
- AI・自動化ツールへの関心が高い

### ニーズとペインポイント

#### 主要ニーズ
| # | ニーズ | 優先度 |
|---|---|---|
| N1 | **一覧性**: 複数の情報を一目で把握したい | 最高 |
| N2 | **素早い操作**: 最小クリックで目的の操作に到達したい | 高 |
| N3 | **横断的な視点**: プロジェクト・タスク・スケジュールを横串で見たい | 高 |
| N4 | **コンテキスト切替の最小化**: 画面遷移を減らし、集中を維持したい | 中 |
| N5 | **データドリブン**: 数値・グラフで客観的に状況判断したい | 中 |

#### 現在のペインポイント
| # | ペインポイント | 影響度 |
|---|---|---|
| P1 | ツールが分散していて全体像が見えにくい | 高 |
| P2 | タスクの優先度判断に時間がかかる | 高 |
| P3 | 個人の「やりたいこと」と業務タスクが混在する | 中 |
| P4 | 学習したい内容が溜まるが復習する仕組みがない | 中 |
| P5 | 時間の使い方を振り返る手段が少ない | 低 |

### 利用シナリオ

#### シナリオ1: 朝の日課 — 全体状況チェック（2分以内）
> ログイン → ダッシュボードで今日の予定・タスク概要を確認 → 気になる項目だけ詳細を開く

#### シナリオ2: 移動中のクイック操作（30秒以内）
> スマホでアクセス → 思いついた「やりたいこと」をサッと登録 → 閉じる

#### シナリオ3: 週次振り返り（5分以内）
> ダッシュボードの時間グラフで1週間を俯瞰 → カテゴリ別の傾向を確認 → 来週の優先度を調整

#### シナリオ4: 学習の積み上げ（隙間時間）
> ActiveRecallで復習通知 → 3問回答 → 定着度を確認

### UI/UXへの期待

#### 視覚デザイン
- **情報密度**: 高め（プロ向け、余白より情報量を優先）
- **配色**: 落ち着いたトーン、ステータスは色で即判別
- **フォント**: 読みやすさ重視、日本語は14px以上
- **アイコン**: テキストよりアイコンで素早く認知

#### インタラクション
- **キーボードショートカット**: パワーユーザー向けの操作性
- **インライン編集**: モーダルより画面遷移なしの編集を好む
- **ドラッグ&ドロップ**: 直感的な並び替え・優先度変更
- **フィルタ/ソート**: 素早い絞り込みが必須

#### レイアウト
- **ダッシュボード**: ウィジェット型、カスタマイズ可能が理想
- **リスト表示**: テーブル形式（カード形式より情報密度が高い）
- **ナビゲーション**: サイドバー常時表示、現在位置が明確

### デバイス・環境

| デバイス | 使用頻度 | 用途 |

| デスクトップ（27インチ+） | 最多 | 日常業務、全機能利用 |

## ペルソナに基づくデザイン原則

### 1. 情報ファースト（Information First）
> PM は大量の情報を横断的に見る必要がある。装飾より情報密度を優先。

### 2. 3クリック以内（3-Click Rule）
> 任意の情報・操作に3クリック以内でアクセスできること。

### 3. スキャン可能（Scannable）
> 目を通すだけで状況が把握できる視覚設計。色・アイコン・バッジで即認知。

### 4. コンテキスト保持（Context Preservation）
> 画面遷移を最小限に。サイドパネル・モーダル・インライン編集を活用。

### 5. プログレッシブ・ディスクロージャ（Progressive Disclosure）
> 初期表示はサマリー、詳細は展開/ドリルダウンで。情報過多を防ぐ。
