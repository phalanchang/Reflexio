# レビューチェックリスト ガイド

## 概要

このディレクトリには、人間がチェックすべき項目を定義したチェックリストが格納されています。

## ファイル構成

- `review_checklist_template.md` - チェックリストのテンプレート
- `01_sprint_01_review_checklist.md` - 1stスプリント用のチェックリスト
- 今後、各スプリントごとにチェックリストを追加

## 使い方

### 1. チェックリストの作成

各スプリントや機能実装ごとに、テンプレートをコピーしてチェックリストを作成します。

```bash
# 例：2ndスプリント用のチェックリストを作成
cp review_checklist_template.md 02_sprint_02_review_checklist.md
```

### 2. チェックの実施

実装完了後、チェックリストに従って確認を行います。

- ✅ チェック完了
- ❌ 問題あり（詳細を記載）
- ⏸️ 保留（理由を記載）

### 3. チェック結果の記録

チェックリストの「チェック結果」セクションに以下を記録します：

- チェック日時
- チェック実施者
- 各項目のチェック結果
- 問題点（あれば）
- 修正内容（あれば）
- 再チェック結果（必要に応じて）

## レコメンド

### チェックリストの配置場所

**推奨：`docs/01_agile/04_review/`配下**

- スプリントごとにチェックリストを作成
- ファイル名は `XX_sprint_XX_review_checklist.md` 形式
- アジャイル開発プロセスと関連付けやすい

### チェック結果の記録方法

**推奨：チェックリストファイル内に記録**

- チェックリストファイルの「チェック結果」セクションに記録
- 履歴を残す場合は、日時ごとに記録を追加
- 必要に応じて、`.ai/shared-context.md`にも記録

### チェックのタイミング

1. **実装完了時** - 各機能実装完了後
2. **スプリント終了時** - スプリント全体のチェック
3. **マージ前** - プルリクエストマージ前の最終チェック

### チェックリストの更新

- 新しい項目が必要になったら、テンプレートを更新
- スプリントごとに必要な項目を追加・削除
- 過去のチェックリストは履歴として残す
