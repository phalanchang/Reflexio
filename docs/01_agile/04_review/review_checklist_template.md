# レビューチェックリスト テンプレート

## 目的
人間がチェックすべき項目を定義し、品質を確保するためのチェックリストです。

## チェックリストの使い方

### 1. チェックリストの作成
- 各スプリントや機能実装ごとにチェックリストを作成
- テンプレートをコピーして使用

### 2. チェックの実施
- 実装完了後、チェックリストに従って確認
- 各項目をチェック（✅ または ❌）

### 3. チェック結果の記録
- チェック日時を記録
- 問題があれば詳細を記載
- 修正が必要な場合は、修正後に再チェック

## チェックリスト項目（カテゴリ別）

### 環境構築
- [ ] Docker環境が正常に起動する
- [ ] 各コンテナが正常に動作する
- [ ] コンテナ間の通信が正常に動作する
- [ ] 環境変数が適切に設定されている
- [ ] ポート設定が正しい

### コード品質
- [ ] コードが読みやすい
- [ ] 命名規則が統一されている
- [ ] コメントが適切に記載されている
- [ ] 不要なコードがない
- [ ] エラーハンドリングが適切

### セキュリティ
- [ ] パスワードがハッシュ化されている
- [ ] SQLインジェクション対策が実装されている
- [ ] XSS対策が実装されている
- [ ] セッション管理が適切
- [ ] 認証が必要なページが保護されている

### 機能要件
- [ ] 要件定義書の機能が実装されている
- [ ] 受け入れ基準を満たしている
- [ ] エッジケースが考慮されている
- [ ] エラーメッセージが適切

### UI/UX
- [ ] レイアウトが要件通り
- [ ] レスポンシブ対応（必要に応じて）
- [ ] ユーザビリティが確保されている
- [ ] アクセシビリティが考慮されている

### パフォーマンス
- [ ] ページ読み込み時間が適切
- [ ] APIレスポンス時間が適切
- [ ] データベースクエリが最適化されている

### ドキュメント
- [ ] READMEが更新されている
- [ ] コードにコメントが記載されている
- [ ] API仕様が記載されている（必要に応じて）

## チェック結果の記録形式

```markdown
## チェック結果

### チェック日時
YYYY-MM-DD HH:MM:SS

### チェック実施者
[名前]

### チェック結果
- [✅/❌] 項目名
  - 備考: [詳細があれば記載]

### 問題点
- [問題があれば記載]

### 修正内容
- [修正があれば記載]

### 再チェック
- [再チェックが必要な場合]
```
