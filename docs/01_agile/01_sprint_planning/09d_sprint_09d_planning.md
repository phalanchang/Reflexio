## 改善6: コンテキストメニュー（⋯ ドロップダウン）

### 現状の問題
テーブルビューの各行に「編集」「削除」がテキストリンクで常時表示されている。カードビューでも同様。
→ 操作が多くなると列が冗長になり、将来の操作追加（ステータス変更等）に対応しにくい。

### 改善内容

**テーブルビュー**: 操作列の「編集」「削除」→ `⋯` アイコン1つに集約

```
⋯ クリック時:
  ┌──────────────────┐
  │ 📝 編集           │
  │ 🔄 ステータス変更  │
  │    → 未着手       │
  │    → 進行中       │
  │    → 完了         │
  │ ─────────────── │
  │ 🗑 削除           │
  └──────────────────┘
```

**カードビュー**: 右上に `⋯` アイコン（ホバー時に表示）

### 実装方針

#### 新コンポーネント: `ActionMenu.js` + `ActionMenu.css`
- props: `wish`, `onEdit`, `onDelete`, `onStatusChange`, `position`
- `⋯` ボタンクリックでドロップダウン表示
- 外部クリックで閉じる（`useEffect` + `document.addEventListener`）
- ESC キーで閉じる
- ステータス変更はサブメニュー（現在のステータスを除く2つを表示）
- z-index: テーブル行のホバーより上（z-index: 100）
- ダークモード対応（CSS変数使用）

#### WishList.js 変更
- `handleStatusChange(wishId, newStatus)` 関数追加
  - PUT `/api/wishes/${wishId}` でステータスのみ更新
  - 成功時にローカル state を即時更新（再fetch不要）
  - トースト通知
- テーブルビュー: 操作列を `<ActionMenu>` に置換
- カードビュー: `.wish-item-actions` を `<ActionMenu>` に置換

#### WishList.css 変更
- `.wish-table-actions` → `<ActionMenu>` 用スタイルに変更
- カードビューの `.wish-item-actions` 配置修正

### 受け入れ基準
- [ ] テーブル行の操作が `⋯` メニューに集約される
- [ ] カードの操作も `⋯` メニューに集約される
- [ ] メニューから編集・削除が動作する
- [ ] メニューからステータス変更ができる（API呼び出し含む）
- [ ] 外部クリック・ESCでメニューが閉じる
- [ ] ダークモードで適切に表示される

## 改善7: 一括操作（バルクアクション）

### 現状の問題
アイテムが増えると、1件ずつステータス変更や削除をするのが非効率。

### 改善内容

**テーブルビュー**: 左端にチェックボックス列を追加

```
┌──┬────────────────┬────────┬─────┬──────┬───────┬────┐
│☑ │ タイトル        │ステータス│優先度│ タグ  │ 期限  │ ⋯ │  ← ヘッダーに全選択
├──┼────────────────┼────────┼─────┼──────┼───────┼────┤
│☑ │ AIの整理...     │ 未着手  │  中  │ AI   │ 3/2   │ ⋯ │
│□ │ OpenClawSetup   │ 完了    │  高  │AI,OC │ 2/22  │ ⋯ │
└──┴────────────────┴────────┴─────┴──────┴───────┴────┘

選択時にフローティングアクションバー表示:
┌─────────────────────────────────────────────┐
│ 2件選択中  [ステータス変更▼] [一括削除]  [✕] │
└─────────────────────────────────────────────┘
```

### 実装方針

#### WishList.js 変更
- `selectedIds` state 追加（`Set<number>`）
- ヘッダーチェックボックス: `filteredWishes` 全件の選択/全解除トグル
- 行チェックボックス: 個別選択
- `handleBulkStatusChange(newStatus)`: 選択アイテム全件をAPI呼び出し
  - `Promise.all` で並行実行
  - 成功/失敗件数をトースト表示
  - 完了後に `selectedIds` クリア
- `handleBulkDelete()`: 確認ダイアログ → 選択アイテム全件削除
  - 「{N}件のアイテムを削除してもよろしいですか？」

#### 新要素: フローティングアクションバー
- `selectedIds.size > 0` の時にテーブル下部に固定表示
- 「N件選択中」+ アクションボタン + 解除ボタン
- `position: sticky; bottom: 0;`
- ダークモード対応

#### カードビューでの対応
- カードビューではチェックボックスなし（テーブルビュー専用機能）
- カードビューは個別操作（コンテキストメニュー）のみ

### 受け入れ基準
- [ ] テーブルの左端にチェックボックスが表示される
- [ ] ヘッダーチェックボックスで全選択/全解除ができる
- [ ] 1件以上選択するとフローティングアクションバーが表示される
- [ ] 一括ステータス変更が動作する（API呼び出し）
- [ ] 一括削除が確認ダイアログ付きで動作する
- [ ] 操作完了後にチェックが解除される
- [ ] ダークモードで適切に表示される
- [ ] カードビューには影響しない

## 改善8: キーボードショートカット

### 現状の問題
マウス操作のみでキーボードだけでの操作ができない。PM/エンジニアはキーボード操作を好む。

### 改善内容

| キー | アクション | 条件 |
|---|---|---|
| `N` | 新規追加（フォーム表示） | フォーム・モーダル非表示時 |
| `E` | 選択行を編集 | テーブルビュー + 1行選択時 |
| `Delete` / `Backspace` | 選択行を削除 | テーブルビュー + 1行以上選択時 |
| `↑` / `↓` | フォーカス行移動 | テーブルビュー時 |
| `/` | 検索フィールドにフォーカス | フォーム・モーダル非表示時 |
| `Escape` | フォーム/モーダル/メニュー閉じる | 対象が開いている時 |
| `Space` | チェックボックス切替 | テーブルビュー + フォーカス行 |
| `?` | ショートカットヘルプ表示 | いつでも |

### 実装方針

#### 新カスタムフック: `useKeyboardShortcuts.js`
- `useEffect` で `keydown` イベントリスナー
- フォーム入力中（`input`, `textarea`, `select` にフォーカス中）は無効化
- `showForm`, `modalImage`, アクションメニュー表示中はショートカット無効化
- 各キーに対応するコールバックをマッピング

#### WishList.js 変更
- `focusedIndex` state 追加（テーブルのフォーカス行）
- `↑`/`↓` でフォーカス移動（`filteredWishes` のインデックス）
- フォーカス行のスタイル: `outline` or 背景色ハイライト
- `useKeyboardShortcuts` フックを呼び出し

#### 新コンポーネント: `ShortcutHelp.js` + `ShortcutHelp.css`（任意）
- `?` キーで表示されるモーダル
- ショートカット一覧テーブル
- ESC / オーバーレイクリックで閉じる
- z-index: SkillModal(1500) と同等

### 受け入れ基準
- [ ] `N` で新規追加フォームが開く
- [ ] `/` で検索フィールドにフォーカスが移る
- [ ] `Escape` でフォーム・モーダル・メニューが閉じる
- [ ] `↑`/`↓` でテーブル行のフォーカスが移動する
- [ ] フォーカス行が視覚的にハイライトされる
- [ ] `Space` でフォーカス行のチェックボックスが切替わる
- [ ] `E` でフォーカス行の編集が開く（1行選択時）
- [ ] `Delete` で選択行の削除が動作する
- [ ] `?` でショートカットヘルプが表示される
- [ ] テキスト入力中はショートカットが無効化される
- [ ] ダークモードで全要素が適切に表示される
