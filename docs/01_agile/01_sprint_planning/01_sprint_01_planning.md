# 01. 1stスプリント計画

## スプリント概要

### スプリント名
1stスプリント：認証機能と基本レイアウトの実装

### 期間
[期間を記載]（例：2週間）

### 目標
- ログイン機能の実装
- 基本レイアウト（ヘッダー、サイドバー、メインコンテンツ）の実装
- ログアウト機能の実装
- Docker環境の構築（フロントエンド、バックエンド、データベース）

## スプリントバックログ

### 優先順位1：環境構築
- Docker環境の構築
  - フロントエンド（React）コンテナ
  - バックエンド（Node.js）コンテナ
  - データベース（MySQL）コンテナ
  - Docker Composeによる連携設定

### 優先順位2：基本レイアウト
- ヘッダー（高さ40px）の実装
- サイドバー（幅250px）の実装
- メインコンテンツ領域の実装
- レスポンシブ対応（将来的に）

### 優先順位3：認証機能
- ログイン画面の実装
- ログインAPIの実装
- セッション管理の実装
- ログアウト機能の実装
- 認証状態の管理

### 優先順位4：ダッシュボード（最小限）
- ダッシュボード画面の基本実装
- サイドバーからのナビゲーション実装

## 成果物

### フロントエンド
- ログイン画面
- メインページ（ヘッダー、サイドバー、メインコンテンツ）
- 基本的なルーティング

### バックエンド
- ログインAPI
- ログアウトAPI
- セッション管理機能
- 認証ミドルウェア

### データベース
- ユーザーテーブルの設計・作成
- セッションテーブルの設計・作成（必要に応じて）

### インフラ
- Docker Compose設定ファイル
- 各サービスのDockerfile

## 受け入れ基準

- [ ] ログイン画面からログインできる
- [ ] ログイン後、メインページが表示される
- [ ] メインページにヘッダー、サイドバー、メインコンテンツが表示される
- [ ] ログアウトボタンからログアウトできる
- [ ] ログアウト後、ログイン画面に戻る
- [ ] Docker環境で正常に動作する

## リスクと課題

### 技術的リスク
- Docker環境の構築に時間がかかる可能性
- 認証方式の選定（JWT、セッション等）

### スケジュールリスク
- 環境構築に予想以上の時間がかかる可能性
