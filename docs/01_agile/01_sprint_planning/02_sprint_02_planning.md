### スプリント名

### 期間

### 目標
- 「やりたいこと」管理機能のDB設計・テーブル作成
- CRUD APIの実装（一覧・追加・編集・削除）
- 基本UIの実装（一覧画面・追加/編集フォーム）
- ステータス管理・優先度管理の基本実装

## 機能概要

「やりたいこと」管理機能は、日常の小さな願望（カフェに行く、映画を観る、本を読む等）を管理するウィッシュリスト機能です。
タスク管理機能とは別の独立した機能として、サイドバーに追加します。

### 管理属性（Sprint 2 スコープ）
| 属性 | 型 | 必須 | 説明 |
|---|---|---|---|
| タイトル | テキスト | 必須 | やりたいことの名前 |
| ステータス | 選択 | 必須 | 未着手 / 進行中 / 完了 |
| 優先度 | 選択 | 必須 | 高 / 中 / 低 |
| 期限 | 日付 | 任意 | いつまでにやりたいか |
| メモ | テキスト | 任意 | 詳細・補足の自由記入 |

### 後続スプリントで実装する属性
- カテゴリ管理（Sprint 3）
- フィルタリング・ソート・検索（Sprint 3）
- 画像添付（Sprint 4）
- URLリンク添付（Sprint 4）

## スプリントバックログ

### 優先順位1：DB設計・構築
- wishesテーブルの設計・作成
  - id, user_id, title, description, status, priority, due_date, created_at, updated_at
- 初期データ投入用SQLの作成

### 優先順位2：バックエンドAPI
- GET /api/wishes - 一覧取得（自分のwishesのみ）
- POST /api/wishes - 新規作成
- PUT /api/wishes/:id - 更新
- DELETE /api/wishes/:id - 削除
- 認証ミドルウェア（requireAuth）の適用
- バリデーション

### 優先順位3：フロントエンドUI
- WishList コンポーネント（一覧画面）
  - ステータスアイコン・優先度表示
  - 完了/未完了の切り替え
- WishForm コンポーネント（追加/編集フォーム）
  - タイトル、ステータス、優先度、期限、メモの入力
- サイドバーへの「やりたいこと」メニュー追加
- App.jsへのルート追加

### 優先順位4：UX改善
- 一覧画面でのステータス別表示
- 空状態の表示
- 成功/エラーメッセージの表示

## 受け入れ基準

- [ ] サイドバーに「やりたいこと」メニューが表示される
- [ ] メニュークリックでやりたいこと一覧画面が表示される
- [ ] 新しい「やりたいこと」を追加できる（タイトル必須）
- [ ] 一覧から「やりたいこと」を編集できる
- [ ] 一覧から「やりたいこと」を削除できる
- [ ] ステータス（未着手/進行中/完了）を設定・変更できる
- [ ] 優先度（高/中/低）を設定・変更できる
- [ ] 期限を設定できる（任意）
- [ ] メモを記入できる（任意）
- [ ] 自分のデータのみ表示される（他ユーザーのデータは見えない）
- [ ] 未ログイン時はアクセスできない（ProtectedRoute）

## リスクと課題

- 既存のusersテーブルとの外部キー設計
